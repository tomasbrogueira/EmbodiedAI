# Hazard deployment cost

`traversability_hazard_benchmark.profile_backend(config, *, backend=None, segmenter=None)` profiles whole-RGB hazard adapters against `segmentation/selection.json`. Freeze the selection before inspecting predictions. The protocol requires five development warmups, twenty test frames (ten per source), and two measured repeats. Package imports do not load Torch, SAM3, Transformers or checkpoints.

Start with `configs/hazards/benchmark.json`. Set portable roots through explicit configuration or `TRAVERSABILITY_DATA_ROOT`, `TRAVERSABILITY_RUN_ROOT`, and `TRAVERSABILITY_CACHE_ROOT`. `component` selects `vlm`, `sam`, or `combined`; `condition_key` selects `vlm__qwen3_vl_4b`, `vlm__qwen3_5_4b`, `reference_present`, or `fixed_policy`. VLM and combined profiles require a VLM condition. SAM-only profiles use the controller's saved original phrases; reference/fixed lists remain diagnostic controller inputs.

Real work is disabled by default. Genuine execution requires an isolated Python 3.12+ environment, pinned/access-authorized checkpoints and dependencies, `enable_real_run=true`, and one explicit `cuda:N` device. A fresh subprocess owns loaded adapters and closes only those resources; it never clears process-wide CUDA caches. Combined execution additionally requires `enable_combined=true`, loads both models on the same device, and measures actual VLM then SAM calls with both resident. Missing dependencies/checkpoint access are saved as unavailable load errors, without substitute models.

Synthetic adapters require `fixture=true` and a non-null `fixture_identity`; injected adapters remain caller-owned. Optional `_clock` and `_memory_probe` test hooks are accepted only in fixture mode. Fixture results always have `comparison_ready=false`, null real budget decisions and no hardware evidence claims.

Artifacts are `benchmark/<condition_key>/<profile_id>/{samples.jsonl,metadata.json,summary.json}`. Inputs, hashes, dimensions, selected joins, policy, condition predictions and adapter settings are validated outside timed intervals before and after calls. A process lock and atomic complete-file replacements preserve every completed attempt. Compatible completed errors remain errors; resume skips those measured slots and performs a separately recorded fresh load/five-warmup session before missing slots. Changed identity requires a new profile ID.

A SAM or combined profile also checks its actual SAM identity against existing segmentation conditions before warmups. The checkpoint/code revision, thresholds, processing, software and fixture identity must match; a different profile ID cannot bypass that experiment contract. Failed VLM responses cannot expose usable prompts, and a missing prompt field is a schema error.

Samples preserve original phrases, raw VLM responses, SAM query errors and returned instance counts, actual SAM call counts, frame/repeat/session identity, synchronized wall time and memory baselines/peaks. Isolated intervals contain exactly the whole adapter call; output auditing and frozen input checks occur outside them. Upstream-blocked SAM attempts have null time and `call_attempted=false`, rather than a fabricated cheap model call. Unexpected adapter crashes may make text-query counts unavailable, marked null with a summary count of unavailable observations. `latency` includes every valid measured attempt, including failures; `successful_latency` and `failed_attempt_latency` separate them. Warmups and loading are excluded from these quantiles. Median/p95 use linear interpolation at `(n-1)*q`. Failed synchronization makes timing null. `complete` describes terminal protocol coverage; ordinary model failures remain comparable explicit outcomes. `comparison_ready` additionally requires genuine provenance and valid complete timing.

Memory reports distinguish current-process allocator allocated/reserved peaks from sampled shared-device usage, retain pre-load and resident/call baselines, incremental peaks and unavailable reasons. Missing telemetry is null. Sampling can miss short peaks; device usage includes other processes. Combined peak counters are reset only around the whole combined call, never inside stage timers. Isolated peaks/p95s are never added, and isolated profiles cannot establish joint fit.

The proposed VLM budget is **6 decimal GB** on a shared **20 GB** GPU; SAM is additional. Fixture/unavailable/incomplete budget status is unmeasured. Genuine VLM allocator measurements may assess the proposed component budget; sampled device usage alone cannot pass it. Joint fit remains unmeasured pending a complete genuine combined replay and available shared-device headroom assessment. No real checkpoint/GPU measurements have been performed during local implementation.
